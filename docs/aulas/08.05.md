# Construindo o projeto JAVA MAVEN e Sincronizando com o GitHub

## 1. Pré-requisitos: O Alicerce do Projeto  

Antes de iniciarmos a construção de qualquer código, seu ambiente deve estar pronto para evitar qualquer dor de cabeça. Se você pulou as etapas anteriores, volte e garanta que:

- **Ambiente Configurado**: O Maven e o Git devem estar acessíveis pelo terminal do VS Code, como nas aulas anteriores.  
- **Repositório Clonado**: Você deve ter uma cópia local do seu projeto dentro da pasta `C:\dev\nome-do-seu-repositorio`. Se a pasta estiver vazia ou não existir, utilize o comando `git clone URL_DO_REPOSITORIO` no diretório `C:\dev\` .  

## 2. O que é o Maven? 
Muitos iniciantes confundem o _Maven_ com a linguagem _Java_, mas eles são coisas diferentes.

O Apache Maven é uma ferramenta de **automação** de compilação e gerenciamento de dependências. Imagine que seu projeto precise de uma biblioteca para conectar ao Banco de Dados. Sem o Maven, você teria que baixar o arquivo .jar (uma dependência) manualmente, colocar na pasta e configurar caminhos. Com o _Maven_, você apenas escreve o nome da biblioteca no arquivo `pom.xml` e ele faz todo o trabalho sujo por você.

As três principais funções do Maven são:

- **Padronização**: Ele cria uma estrutura de pastas padrão (src/main/java).
- **Gestão de Dependências**: Baixa e atualiza bibliotecas externas automaticamente.
- **Ciclo de Vida**: Compila, testa e empacota seu projeto com comandos simples.

## 3. Fluxo de Trabalho: O Ciclo de Sanidade do Desenvolvedor
Trabalhar no **desenvolvimento de software** exige organização por ser uma atividade **complexa** e **colaborativa**. Se dois desenvolvedores mexem no mesmo arquivo sem ordem, o caos se instala. Por isso, seguimos este **ciclo lógico e obrigatório**:

### 3.1. Sincronizar (git pull)

Antes de digitar uma única linha de código, você deve trazer as atualizações do servidor para sua máquina local.
> O comando `git pull`, antes de iniciar qualquer mudança no seu repositório local, garante que você está trabalhando na versão mais recente do projeto e evitar conflitos com o trabalho de seus colegas que já foi enviado ao GitHub.

### 3.3. Preparar (git add .)
Você terminou uma parte do trabalho? Agora precisa avisar ao Git quais arquivos devem entrar no próximo ponto de evolução (commit).

Porém, nem tudo que foi criado, precisa ser enviado, precisamos deixar arquivos que são gerados (ex.: _class_) na maquina local, o que precisa ser enviado é apenas a fonte 
que deu origem ao arquivo _class_. Para isso, precisamos criar um arquivo `.gitignore` no diretório raiz do repositório para informar para o `git` quais arquivos ou diretórios são esses.

``` .gitignore

target/
pom.xml.tag
pom.xml.releaseBackup
pom.xml.versionsBackup
pom.xml.next
release.properties
dependency-reduced-pom.xml
buildNumber.properties
.mvn/timing.properties
# https://maven.apache.org/wrapper/#usage-without-binary-jar
.mvn/wrapper/maven-wrapper.jar

# Eclipse m2e generated files
# Eclipse Core
.project
# JDT-specific (Eclipse Java Development Tools)
.classpath

```

### 3.4. Registrar (git commit -m "mensagem")
Agora você salva permanentemente essa versão na sua máquina local.

> O comando `git commit -m "Criando a estrutura inicial do projeto maven"` cria um ponto de restauração. Se algo der errado no futuro, você pode voltar exatamente para este momento. A mensagem deve ser clara e descrever o que foi feito.

### 3.5. Publicar (git push)
Até agora, tudo está apenas no seu computador. Se seu HD quebrar, você perde tudo.

> O comando git push os seus pontons de evolução/restauração local para o servidor do GitHub. Agora, seu professor e seus colegas podem ver e baixar o seu código.
